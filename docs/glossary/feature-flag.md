# Feature flag

**Feature flag** is a named on/off value. Code defaults live in `FeatureFlagsCatalog` ([`src/UI/Api/FeatureFlagsCatalog.cs`](../../src/UI/Api/FeatureFlagsCatalog.cs)): `SampleFeatureA` is enabled, `SampleFeatureB` is disabled, `ShowPriorityBadges` is enabled, and `BuildingManagement` and `VendorManagement` are disabled. `IFeatureFlagRuntime` overlays the `FeatureFlags` configuration section on those defaults, and `GET /api/features/flags`, `GET /api/v1.0/features/flags`, and `featureFlags` on `GET /api/diagnostics` return that one map ([`FeatureFlagsController`](../../src/UI/Api/Controllers/FeatureFlagsController.cs), [`DiagnosticsController`](../../src/UI/Api/Controllers/DiagnosticsController.cs)). The Blazor client reads the flags through `IFeatureFlags` ([`src/UI.Shared/Services/IFeatureFlags.cs`](../../src/UI.Shared/Services/IFeatureFlags.cs), [`HttpFeatureFlags`](../../src/UI/Client/HttpFeatureFlags.cs)). When `ShowPriorityBadges` is enabled, a High-priority work order shows a colored badge on the search list and the board. `BuildingManagement` and `VendorManagement` stay off in code and in the image (platform uat and prod until flipped) and are on for platform tdd and the local Development host, which is also the acceptance host ([Feature flags](../ops/feature-flags.md)).
